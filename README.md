## 遊戲介紹

你在青嶺醫療中心的夜班中醒來。病房需要查房，急診打來會診電話，另一棟院區還有人等著你。這些工作熟悉得近乎本能，只有自己的名字，始終無法確定。

護理站電腦上的欄位、牆上的老照片、警衛口中的往事，都像在描述同一個夜晚，卻又留下彼此不一致的細節。你必須親自走過走廊、接起電話、核對醫囑單，分辨眼前發生的事、別人說過的事，以及身體以為自己記得的事。

**《夜班迴廊 Version 2》把「我是誰」放進實際遊玩，而不是先給你角色介紹，再要你尋找他的故事。** 同一座醫院，在不同回合會以不同起點、任務順序與第一人稱反應展開。你經過哪些地方、注意哪些細節、如何做出判斷，都是理解這一輪記憶的線索。

| 遊玩資訊 | 說明 |
| --- | --- |
| 類型 | 單人、第一人稱 3D 探索、敘事解謎與心理恐怖 |
| 平台 | 瀏覽器網頁版，不需另行安裝遊戲主程式 |
| 語言 | 以繁體中文敘事為主，部分院內系統介面保留英文 |

| 開發狀態 | 持續更新的試玩版本；已完成關鍵互動驗收，不代表所有路線與裝置均已完整驗收 |

## Version 2 的特色

### 同一座醫院，四種夜班經驗

四條路線共用院區、照片、相簿、海報與場景物件，但不只是替換姓名。同一個空間可以引出不同的聯想；不同的來電、交班與回訪順序，讓你逐漸看出這一輪經驗的輪廓。正常遊玩時不會先揭露當前身分。

### 用現場互動推進，而不只是閱讀文件

走到護理站電腦、接起桌上的電話、翻閱相簿、檢查物件與回到病房，都是故事的一部分。主要任務會指向場景中的實體物件；一般照片與海報也能提供觀察，不必每次都被算成主線任務。

### 記憶、紀錄與判斷可能不一致

一張完整的醫囑單，不一定足以證明事情真的發生過；一個熟悉的動作，也不一定代表判斷正確。遊戲讓你在觀察與行動之間作出選擇，並面對這些選擇的後果。部分重要提交不可撤銷，請先讀完遊戲中的提示。

### 寫實醫院空間與克制的恐怖演出

場景以寫實醫院為美術方向，結合 3D 模型、材質、護理工作站、值班室與衛浴細節。檔案影像採一致的照片閱讀介面，保留原始比例；恐怖氣氛來自光線、電話、腳步、敲擊與短暫的視覺異常，而不靠介紹頁提前解釋謎底。

### 隨路線與空間變化的聲音

四條路線各有主題動機。原創合成配樂透過分句與和聲變化，回應探索、休息、監控與異常事件；來電及重要音效出現時，背景音樂會降低音量。它不是單一固定長音，也不是外部錄製的原聲帶。

## 開始遊玩

1. 開啟 **[正式試玩入口](https://hsushuhao-lab.github.io/Identity-Loop/)**，等待必要場景資料載入，再點擊開始。
2. 先看畫面上的「目前任務」。靠近對應物件，將準星移到它身上，出現互動提示後按 **E**。
3. 讀完對話或文件，再依目前任務前往下一個地點。遇到需要判斷的選項，先區分已確認的事與尚待核對的事。

請使用目前的 **`Identity-Loop`** 網址。舊版拼寫的試玩書籤已不再作為正式入口；倉庫連結與遊戲入口也不是同一個頁面。

## 操作方式

| 操作 | 功能 |
| --- | --- |
| **W / A / S / D** | 前進、左移、後退、右移；方向鍵也可行走 |
| **滑鼠** | 在遊戲畫面取得滑鼠控制後轉動視角 |
| **Shift** | 快走 |
| **E** | 與準星指向的物件互動；對話中按 E 繼續 |
| **滑鼠雙擊** | 嘗試自動走近指向的位置；仍受碰撞限制，不會自動繞過障礙 |
| **A / D 或 ← / →** | 相簿開啟時切換上一頁／下一頁，也可使用畫面按鈕 |
| **Esc** | 釋放滑鼠控制，或關閉支援關閉的閱讀介面；不是全遊戲暫停鍵 |
| **畫面上的按鈕與輸入欄** | 操作選項、文件、密碼鎖及其他需要確認的介面 |

關閉文件後，必要時再點擊遊戲畫面取回滑鼠控制。聲音需要開始點擊或鍵盤操作後才能啟用；請先用適中的系統音量遊玩。

**裝置範圍：**目前以桌機／筆電的鍵盤與滑鼠操作為主。部分 390px 窄螢幕介面已驗證，但不等於整個遊戲已完成手機實機觸控驗收，也不代表所有瀏覽器與顯示晶片都已通過測試。

## 存檔與更新

回合身分、路線步驟、已記錄的證據與已取得的結局，使用**目前瀏覽器的本機儲存**保存。重新整理不等於抽取新身分；一般更新也不需要清除網站資料。

這不是雲端存檔。換裝置、換瀏覽器，或清除網站資料，可能讀不到原本的進度。也不要把它理解成任意瞬間存檔：系統以路線章節恢復為主，不保證保留重新整理前的站立位置、對話頁數、未提交選項或事件中途的所有狀態。

較早版本的擴充路線已加入章節遷移。舊回合若已越過新增任務所在的位置，不會強迫倒退，也不會把沒玩過的任務標成已完成。要完整體驗新加入的內容，請在可開始新回合時使用畫面上的「開始新的夜班」，不必先刪除已取得的結局紀錄。

<summary><strong>常見問題與回報方式</strong></summary>

### 網頁顯示 404

先確認網址為 **https://hsushuhao-lab.github.io/Identity-Loop/**，不要使用舊拼寫的書籤或測試分支網址。

### 更新後看起來還是舊版

先一般重新整理；電腦版也可使用 **Ctrl + Shift + R** 重新載入。不要先清除網站資料，以免影響本機存檔。若仍有差異，回報網址、重新整理時間與畫面即可。

### 看得到物件，卻沒有互動提示

先確認目前任務是否要求該物件，關閉仍開啟的文件或對話，再靠近並用準星指向物件本體。不是所有擺設都能互動。若主線明確要求它卻仍按不到，請回報卡住前的操作，不必用清除存檔代替問題追查。

### 沒有聲音

先點擊開始或遊戲畫面，再確認分頁與系統音量沒有被靜音。音效與背景音樂都應以不刺耳的音量聆聽。

### 要玩多久？四條路線一樣長嗎？

目前未完成四線無輔助全程的通關時間量測。路線步數不等於遊玩分鐘數，也不代表四線時長已完全一致；閱讀、探索與解謎速度都會影響時間。

### 如何回報

請到 **[GitHub Issues](https://github.com/hsushuhao-lab/Identity-Loop/issues)** 留下：使用的網址、作業系統／瀏覽器、院區與樓層、畫面上的目前任務、卡住前的操作、預期結果與實際結果。能附截圖時，請一併附上；含身分答案或結局的內容請標示「劇透」。不需要提供完整瀏覽器儲存資料、密碼或任何真實病人資料。

### 本機執行

使用與目前部署一致的 **Node.js 22**，在倉庫根目錄執行：

```bash
cd prototype
npm ci
npm run dev
```

依終端顯示的本機網址開啟遊戲。Windows 亦保留根目錄的 `run-prototype.cmd`；依賴版本以 `package-lock.json` 為準。

### 建置與驗證

以下指令皆在 `prototype/` 執行：

```bash
npm run test:identity
npm run build
```

需要本機預覽正式建置時，執行 `npm run preview`，並使用終端顯示的網址。

最近互動修正的瀏覽器檢查：

```bash
npx playwright install --with-deps chromium
node scripts/test-clinical-interactions-browser.mjs qa-results/clinical-v2/clinical
node scripts/test-first-duty-bathroom-browser.mjs qa-results/clinical-v2/first-bathroom
node scripts/test-identity-m6-cg-browser.mjs qa-results/clinical-v2/m6
```

`test:identity` 並不代表已執行所有瀏覽器檢查。正式發布的完整結構檢查清單，以 [deploy-pages.yml](.github/workflows/deploy-pages.yml) 當下內容為準。

### 哪個版本才算已上線？

- **設計目標：**以目前採用的 Version 2 規格、角色與美術規範界定；設計稿寫有某功能，不代表它已實裝。
- **實作狀態：**查 `main` 的路線表、互動導演、場景資料與實際 runtime，不以舊對話或資料夾名稱替代。
- **發布狀態：**確認對應提交的 Pages 部署成功，且公開版本指紋吻合；再查看所需的正式站操作證據。

路線長度與排序以 `IdentityRoutes.js` 為準；互動綁定與台詞分別查 `IdentityRouteDirector.js`、`IdentityRouteScenes.js`。`IdentityManager.js` 管理回合與持久狀態。共享歷史敘事與角色資料仍需與 `NarrativeV22.js`、`CharacterBible.js` 及 `main.js` 的整合一致。

不要以過期 feature/fix 分支、舊建置檔、舊截圖或 UE5／Act 1 交班封包作為當前實作基底。需追溯舊資料時使用 Git 歷史，不要把舊封包還原進工作分支。

測試產生的截圖、走查錄影、一次性比較資料與 QA 證據應存為 GitHub Actions artifacts，不回填到正式原始碼樹。`node_modules`、`dist` 與暫存修補檔也不應混入來源提交。較早的設計參考圖不是目前遊戲畫面的證明。
